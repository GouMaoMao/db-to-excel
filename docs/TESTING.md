# DB2Sheet 测试指南

界面、SQL 页和批量刷新的细则见 `.github/copilot-instructions.md`。本文只列要验证的行为。

## 测试分工

### 需要人工执行

- 在真实 Excel 桌面宿主中确认 VSTO 加载。
- 操作 Ribbon 和 Windows Forms。
- 提供可访问的测试数据库。
- 观察 Excel UI 响应、取消体验和最终 Sheet 内容。
- 验证 Advanced Installer 安装、卸载和升级。

## 当前验证状态

解决方案引用 `DB2Sheet.Tests`（.NET Framework 4.7.2、MSTest v2）。该目录在 `.gitignore` 中，当前工作区没有这份源码。本文不记录测试通过个数。

不依赖 Excel COM、可以在本机测试项目里覆盖的逻辑包括：

- SQL 只读校验。JDBC 允许查询前的 `SET`，最后必须是一条 `SELECT` 或 `WITH`。
- 设置注册、类型检查、未知键保留和损坏 JSON 备份。
- SQL 页二维单元格解析：每列一个任务，第 1 行表名和 `//` 参数，第 2 行起非空单元格拼成 SQL，空目标或空 SQL 跳过。
- 连接方案仓储，以及查询方案仓储（`queries\` 下一方案一文件，并迁移旧版 `queries.json`）。

## 后续自动化测试范围

`BatchRefreshService` 的公共入口和结果写入器直接依赖 Excel COM `Workbook`，并要求 Excel UI `SynchronizationContext`。这些场景留在下面的人工清单里，不建 Office COM mock。

## 人工 Excel 集成测试清单

### 加载和 Ribbon

- [ ] 从 Visual Studio 启动 Excel，无加载异常。
- [ ] 显示 Ribbon 标签，文字为「db-to-excel」（`AppPresentation.DisplayName`）。
- [ ] 「SQL 查询」打开查询窗体。再次点击只激活已打开的窗体。
- [ ] 「批量刷新」在存在 `SQL` 工作表时打开刷新窗体。再次点击只激活已打开的窗体。没有该工作表时提示错误，不打开窗体。
- [ ] 「连接管理」打开连接管理窗体。
- [ ] 「设置」下的「参数设置」打开动态设置窗体。
- [ ] 「设置」下的「JDBC 环境」打开 Java 检测窗体。
- [ ] 「设置」下的「本地数据」列出连接、查询和 Skill 等路径，不改保存位置。
- [ ] 「关于」中的版本按钮显示当前版本。

### 连接管理

对 SQL Server、MySQL、PostgreSQL、SQLite、DuckDB 分别执行。JDBC 另需在「JDBC 环境」中检测或指定 `java.exe`，并在连接方案里填写 JDBC URL、驱动 jar 和驱动类。

- [ ] 动态参数字段正确显示。
- [ ] 必填字段校验有效。
- [ ] 测试连接成功。
- [ ] 错误凭据显示清晰错误。
- [ ] 测试过程中可取消。
- [ ] 保存、编辑、删除后两个业务窗体同步刷新连接列表。

### SQL 查询窗体

- [ ] 多个查询页签可同时打开、切换、重命名和关闭。关掉最后一个页签后提示新建查询。
- [ ] 保存新查询方案。
- [ ] 修改并覆盖已有方案。
- [ ] 删除方案。
- [ ] 重新打开窗体后方案仍存在，文件在 `%LocalAppData%\DB2Sheet\queries`。
- [ ] 只读 SQL 可执行。
- [ ] 写操作或多语句被拒绝。JDBC 上，查询前的 `SET` 可以执行。
- [ ] 预览行数受设置限制。
- [ ] 预览数据格右键可复制选区；没有选区时复制全部数据行。复制带标题含字段编码和类型短名两行。
- [ ] 预览列标题右键只复制该列的字段编码和类型短名。
- [ ] 导出为 Excel 先选择路径。生成的 xlsx 含当前预览，能被 Excel 或 WPS 打开，当前工作簿内容不变。成功后要点确定才回到查询窗；取消不出现该框。
- [ ] 空结果能显示列名且不报错。
- [ ] 大结果达到限制后显示截断状态。
- [ ] 取消长查询后 Excel 和窗体可继续使用。
- [ ] 写入目标 Sheet 后标题和数据正确。成功后要点确定才回到查询窗，截断时说明里写出上限；取消不出现该框。美化失败时只出现错误详情。
- [ ] 原目标 Sheet 已用区域里的值被清空，结果从 A1 写入。原有数值格式、字体、对齐、填充还在；新行不套用。
- [ ] 非法 Sheet 名得到明确提示。

### SQL Sheet 批量刷新

准备固定名称 `SQL` 的工作表。每列一个任务。第 1 行写目标表名，可在 `//` 后写参数。第 2 行起写 SQL，可跨多个单元格。参数和注释的细则见 `.github/copilot-instructions.md`。

验证：

- [ ] 重新扫描后任务数量、源列和目标名称正确。
- [ ] 空列、空目标和空 SQL 被忽略。
- [ ] 「起始单元格」和「清空多余列」按参数执行；两个值都是默认且没有其他键时，首行只留表名。
- [ ] 目标表里原有数值格式、字体、对齐、填充还在；新行不套用。结果变短后，多出来的空行不再留着网格线。
- [ ] 参数写错时，刷新前的对话框列出目标表和具体原因；已勾选任务全部写坏时不开始刷新。
- [ ] 串行模式按任务执行。
- [ ] 并行模式遵守最大并发数，Excel 写入仍串行，且没有跨线程 COM 异常。
- [ ] 目标表名忽略大小写后重复时，提示错误，不写入任何表。
- [ ] 某个任务失败时其他任务继续。
- [ ] 取消后未完成任务停止，不弹出结束后的计数说明。
- [ ] 「格式 / 美化格式」按 `.github/copilot-instructions.md` 的「批量刷新」验收：上色与冻结首行，不改 SQL 文字。手动美化成功，或没有可美化的列时，要点确定才回到窗体；取消不出现该框。刷新结束后的自动美化不另加框。
- [ ] 正常结束后的说明按同一节验收：计数、失败和截断明细，以及底部图例。取消或异常不弹出该说明。

### 生命周期和稳定性

- [ ] 查询窗体打开时切换活动工作簿。
- [ ] 查询窗体打开时关闭其绑定工作簿。
- [ ] 批量刷新期间尝试关闭工作簿或 Excel。
- [ ] 多次打开和关闭窗体后无明显 COM 残留或 Excel.exe 无法退出。
- [ ] 插件重启后连接、查询方案、设置和 JDBC 环境仍存在。
- [ ] 日志中不出现明文密码、Token 或连接字符串。查询日志可以包含 SQL 正文。

## 问题反馈信息

人工测试发现问题时，请提供：

1. 操作步骤。
2. 预期结果和实际结果。
3. 完整错误消息或截图。
4. Visual Studio「调试」输出。
5. `%LocalAppData%\DB2Sheet\Logs` 中对应时间的日志。
6. 使用的数据库类型，不要提供真实密码。

## 完成标准

- 本机若有 `DB2Sheet.Tests`，其中的测试全部通过。本文不记录通过个数。
- Debug 和 Release 构建成功。
- SQL Server、MySQL、PostgreSQL、SQLite、DuckDB 至少各完成一次连接测试；配置了 Java 和驱动 jar 时，JDBC 也完成一次。可用环境中的数据库完成查询验证。
- Ribbon、SQL 查询、批量刷新、取消、超时通过人工验收。
- Excel 可正常退出，无持续残留进程。
