# AI 助手规格

适用：SQL 查询的 AI 对话栏、对话页签、模型设置、Skill 设置、思考强度、请求构造、审计与标题生成。

触发：修改 `UI/AiChat*.cs`、`UI/AiModelSettingsForm.cs`、`UI/AiSkillSettingsForm.cs`、`Services/Ai*.cs`、`Storage/Ai*.cs`、`Prompts/*.md` 之前，先完整读本文。

通用窗体、按钮、悬浮说明、芯片和「×」标记规则见 `ui-common.md`。

## 规则

- 功能区路径是「设置」→「AI 设置」→「模型设置」和「Skill 设置」。「AI 设置」和「模型设置」用机器人图标，「Skill 设置」用 Skill 图标。协议只有 OpenAI 兼容、Claude、Gemini 三类，不预填厂商地址或模型名。窗体顶部说明这三类分别对应哪些模型。
- 模型密钥用当前 Windows 用户的 DPAPI 加密后写入 `ai-models.json`，不明文回显，不写入审计日志。Skill 在 `ai-skills\`，一条对话一个文件在 `ai-conversations\`。这三类都不进参数设置。
- SQL 查询标题栏有「AI」按钮，图标用机器人。点开后窗体变宽，在最右侧多出对话栏，SQL 列的像素宽度保持不变；再点收起，窗体收回这段宽度。对话栏页签行右上角从右往左是关闭图标、已归档、新建对话。关闭图标与再点一次「AI」是同一次收起。新建对话与右键「新建」相同。已归档点开与右键「已归档」同一份列表，没有归档时说明不可用。没有对话时这两颗按钮仍留在页签条上。弹出的报错对话窗没有关闭图标，新建和已归档仍在。窗口已最大化，或加宽后会超出工作区时，只加到工作区边缘，放不下的部分由 SQL 列让出。宽度只有用户拖动分割条才写入 `session.aiChatSplitRatio`；是否展开写入 `session.aiChatVisible`。比例为 0 时，对话栏为当时 SQL 列的 2/3，这个默认值不写入设置。下次打开时若上次关闭前对话栏是展开的，窗体尺寸里已经含这段宽度，只按比例摆分割条。
- 查询预览失败，以及写入 Sheet 时查询本身失败，错误详情有「问 AI」。点后弹出独立对话窗，新建标题为「SQL 报错」的对话，把去掉 JDBC 地址、连接串和密码样式片段后的 SQL 与错误摘要填进输入框，不自动发送。不附带堆栈。连接测试、JDBC 环境、美化格式和批量刷新没有这颗按钮。
- 对话用页签切换。右键页签可以新建、重命名、归档和删除；点在空白处只有新建。没有对话时，正文区居中放一颗平按钮「请新建对话」，底色与空白区相同，没有边框和凹凸，点击即新建。周围空白处右键弹出同一个菜单，只有新建和已归档可用。点空白处的左键不新建。页签标题左侧是对话图标，末尾是比标题字大一号的「×」。点「×」归档；没有消息的「新对话」点「×」直接删除文件。右键删除有内容的对话时先确认。归档只从页签收起，可从「已归档」恢复。删除只删除对话文件，不删除审计记录。
- 对话正文用 WebView2 显示 Markdown。助手气泡在左、浅灰，用户气泡在右、浅蓝。助手气泡下，响应同时给出输入和输出 token 时显示灰色小字，例如 ↑2,987 ↓234 tokens。缺一边、只有合计或没返回时不显示，没有悬停说明。用户气泡下，这一轮留有发送原文时显示灰色「查看请求详情」。点开只读小窗。色条上方写出这次的请求地址（POST 和实际发出的地址）、协议、模型、发送时间，以及响应。等待中响应写「尚未返回」；收到回复后写 HTTP 状态和耗时，例如「HTTP 200，耗时 1,234 毫秒」。没有记下这些的旧对话写「这次没有记下请求地址和模型。」不显示密钥和请求头。色条仍在这些行下面。有输入 token 时条下写「本次请求输入占用「N」tokens，各段 token 为估算。」；没有时写输入 token 尚未返回，各段仍为估算。分类默认收起，点开才看原文，空段写「空」。WebView2 初始化失败时同一窗口改回纯文本。旧对话没有这两处。模型原文里的 HTML 和脚本按文字显示，不执行。代码块右上角有复制图标，把该块文字放进剪贴板，不自动写入查询。复制成功后图标旁短暂显示「已复制」，失败显示「复制失败」，约 1.5 秒后自己消失，不弹出窗体。本机需要 Evergreen WebView2 运行库；没有时对话区说明缺少运行库。插件不下载该运行库，安装包也不附带固定版运行库。`WebView2Loader.dll` 按 Excel 位数放在插件目录并写入 VSTO 清单。浏览器数据在 `%LocalAppData%\DB2Sheet\webview2`。
- Skill 和当前查询页签引用放在输入框上方，模型放在输入框下方。发送按钮与模型芯片同一行，靠右。输入框下方有一行灰色说明。每次新建查询窗时从下面六条里抽一条，这次打开期间不换；已经打开时再点功能区只激活，说明不变。报错弹出的对话窗在创建时同样抽一条，关窗前不变。连续两次不抽到同一条。六条是：「输入 @ 可附加查询方案、文件或当前预览。」「复制AI生成的SQL代码到SQL编辑器区域执行。使用者必须理解SQL代码逻辑，再使用。」「模型切换：不同模型在生成质量、响应速度、Token消耗上存在区别。」「Skills：为AI注入场景知识，显著提升生成SQL的准确性。」「Token：对话文本的计费单位，描述越简洁消耗越低；不建议引用MB级别的文件给AI，会大幅增加token消耗。」「对话过长、更换业务查询需求时建议新开对话，减少历史对话干扰，降低Token开销。」字号 8.25，按宽度换行，底栏跟着变高，全文都显示。Skill、引用和模型芯片与这行说明同字号。发送按钮是正文 9 磅，左侧为 24 像素发送图标，比芯片大，左右留空不贴着图标和文字，所在行按按钮高度留出。三者都是比窗体底色略深的芯片，各有悬浮提示，说明用途和到哪里配置。模型和 Skill 点开菜单。模型收起时只显示子型号、图标和末尾的「﹀」；点开后按模型配置分组，每个配置名是可展开项，子型号在下级菜单中并可直接选择。有上方条目时，末项前有一条分隔线；没有模型时菜单里只有末项。末项是加号图标加「新增其他模型」，点开与功能区相同的模型设置，不改当前选择，已有配置时仍选中第一项。Skill 菜单末项是同一加号图标加「新增其他 Skill」，点开 Skill 设置，规则相同。Skill 设置左侧列表是图标加名称。末项是加号和「新增」，上面有 Skill 时先有分隔线，点中后保持选中高亮。右键某一条可以删除。右侧上方是名称，下方是内容。顶部说明 Skill 只是发给模型的文字，用来帮助理解需求，不会执行。模型设置列表按配置名分组，配置父项显示图标和名称，默认配置再加「（默认）」，父项不拼型号；点击父项展开或收起缩进的子型号，初始全部收起，子型号仅展示。列表末项是加号和「新增」，上面有配置时先有分隔线。点该项清空右侧，开始填写一条新的模型配置，该项保持选中高亮。在某一条配置上右键可以删除。设置里填写显示名、协议、接口地址和密钥，不填写子型号。显示名下方灰字建议注明 API 来源是官方还是平台；协议、接口地址、密钥下方灰字分别说明多数选 OpenAI 兼容、地址由服务商提供、密钥在服务商 API 平台生成。测试向接口读取型号并探测一次，通过后才能保存，列表随配置记下。已保存的密钥以固定掩码显示，不明文回显。上次选中的子型号记在 `session.aiModelChoice`。上次勾选的 Skill 记在 `session.aiSkillChoice`。有查询页签时引用默认显示其标题（含未保存标记）并在末尾带比正文大一号的「×」，点标记才删掉。删掉后这一次发送不附带该页签 SQL，审计按没有页签记录。发送结束后引用再按当时的当前页签出现。可以勾选多条。未选用时图标为灰色，文字是 Skills；只选一条时图标为原色并显示名称；选了多条时图标为原色，文字是个数，例如「3 个 Skill」。发送时按列表顺序把每条正文接在系统说明后面。
- 模型芯片右侧、发送按钮左侧是带 `Resources\icon_reasoning_effort.png` 的思考强度选择，选项为「自动 / 低 / 中 / 高」，默认自动并记在 `session.aiThinkingLevel`。思考强度到 API 参数由 `%LocalAppData%\DB2Sheet\ai-thinking-mappings.json` 映射；首次从嵌入默认配置生成，后续不覆盖。按协议、接口主机和可选型号规则匹配，用户可编辑 JSON 为自定义网关增加映射；自动始终不发送强度参数，也不依赖映射文件。DeepSeek 映射可以同时设置 `thinking.type=enabled` 和 `reasoning_effort`。手动档位没有匹配、冲突或配置格式错误时阻止发送并显示错误详情。映射只允许更改非内容请求参数。
- 给 AI 的系统提示词仍只放在 `Prompts/*.md`。SQL 注释写明 AI 生成、模型配置显示名、子型号和思考强度。查看请求详情时显示当次思考强度与实际请求的非内容 API 参数，不展示消息正文、认证头或密钥；旧对话继续可查看。
- 在输入框输入 @ 弹出引用：已保存的查询方案、文件、当前页预览。每行文字左侧有类型图标。选中后删掉输入框里的 @，引用出现在输入框上方，文字用链接色，左侧是同一套图标，末尾是比正文大一号的「×」，点标记才去掉。查询方案和当前查询页签用脚本图标，预览用表格图标，文件用文件图标，其他用附件图标。标签左右各留 4 像素间隔。文件只收文本，最多 64KB。预览用当前页已有结果，最多 30 行、约 16KB，不重新查询。这些引用只对这一次发送有效。
- 未勾选任何 Skill 时，输入框下方的说明改为红字提醒：本次未附带 Skill，模型可能不了解库表结构和含义，生成的 SQL 可用性可能较差，建议前往「设置 → AI 设置 → Skill 设置」配置具体业务场景的 Skill 并勾选。勾选后恢复本窗口原来抽中的说明和灰色，不重新抽取；取消全部勾选后再次显示红字提醒。复用原说明的字号和自动换行，不另加一行，不弹窗，不阻止发送，不记提醒次数。查询侧栏和报错对话窗共用此规则。
- Enter 发送，Shift+Enter 在输入框里换行。正在等待回复时，输入框和发送按钮禁用，图标为灰色，Enter 不重复发送。弹出引用时 Enter 选中该项。发送按钮的悬浮提示写明这次会带上什么、不会带上什么，以及这两句按键。
- 点发送时，若页签引用还在，读取 SQL 编辑器当前页签全文，连同系统说明、所选 Skill、已有往来、用户输入、@ 附上的引用和当前连接的数据库类型名称一起发送。没有页签或引用已删掉时标明 SQL 为空。不自动发送结果行、连接地址、密码和库表目录；只有用 @ 附上预览时才发送那次预览。JDBC 只标明方言未知。等待时对话里、刚发出的问题下面显示三个圆点，不用进度条。回复到达后圆点换成正文。等待不占用 Excel 界面线程。对话文件保存用户输入、助手回复、服务商返回的输入和输出 token，以及发送前按类留存的原文（问题、默认说明、Skill、数据库类型、查询页签、引用、此前问答）。这份原文不脱敏，只供本机查看。发给模型的 HTTP 正文和审计日志仍先脱敏。引用正文同时进审计。标题未锁定时，第一条用户消息先用前 18 个字占位。回复显示后，若这是第 1、3、7 或 13 次用户消息，再用同一模型另起一次短请求生成标题，不附带 SQL、Skill 和引用，也不锁定标题。第 13 轮之后不再自动改。用户重命名或「SQL 报错」保持锁定。这次请求失败或回空则留下原标题，不弹错误详情。
- 发给模型的系统说明、用户消息骨架、引用接法、Skill 接法、报错草稿和标题请求只写在嵌入的 `Prompts/*.md`。代码只填 `{{占位}}`。不要在 C# 字符串里再写一段提示词。系统说明带上本次选用的子型号。给出 SQL 时在注释中标明由 AI 生成和该子型号，并说明用途与关键子句。信息不足以确定查询时只追问，不编造表、字段、关联或业务口径。
- 回复里的代码由用户自己复制，不新建查询页签，也不粘贴、不执行。
- 呼叫模型前先把将要发出的内容写入 `Logs\ai-audit-yyyyMMdd.log`。写失败就不发送。日常日志只留不含正文的一行索引。
- `session.formBounds` 另外记住模型设置、Skill 设置和弹出的 AI 对话窗。
